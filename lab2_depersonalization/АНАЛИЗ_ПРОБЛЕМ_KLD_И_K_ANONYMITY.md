## 🔬 ГЛУБОКИЙ АНАЛИЗ KLD

### Что такое KLD?

KLD(P||Q) = Σ P(i) × log₂(P(i)/Q(i))

- Измеряет различие между распределениями P и Q
- KLD=0: идентичные распределения
- KLD>0: распределения различаются

### Традиционные пороги (0.1, 0.5, 1.0, 2.0)

Эти пороги применяются для **МЯГКОГО** обезличивания:
- Добавление шума: 25 → 24.8
- Легкое обобщение: "25 лет" → "20-30 лет"

### ВАШЕ обезличивание - АГРЕССИВНОЕ!

Примеры:
```
Дата: 529 уникальных дат → 2 квартала (Compression: 264x!)
Симптомы: 553 вариантов → 2 группы (Compression: 277x!)
ФИО: 277 имен → 2 пола (Compression: 139x!)
```

**РЕЗУЛЬТАТ:** Распределения меняются КАРДИНАЛЬНО!

До: P(конкретная дата) = 1/529 ≈ 0.2%
После: P(квартал) = 500/1000 ≈ 50%

Изменение вероятности на **250x** → KLD будет высоким!

## ✅ ПРАВИЛЬНАЯ ИНТЕРПРЕТАЦИЯ KLD

### Проблема №1: KLD применяется к НЕПРАВИЛЬНЫМ атрибутам

**ВАЖНО:** KLD имеет смысл только для атрибутов с **ОБОБЩЕНИЕМ**, не с **ЗАМЕНОЙ**!

**ОБОБЩЕНИЕ** (KLD применим):
- Дата "2025-09-10" → "2025-Q3" ✓
- Стоимость "680 руб" → "До 1000 руб" ✓
- Врач "терапевт" → "Общая медицина" ✓

**ЗАМЕНА** (KLD НЕ применим):
- ФИО → Пол ✗ (это ДРУГОЙ атрибут!)
- СНИЛС → Возраст ✗ (СНИЛС не содержит возраст)
- Паспорт → Регион ✗ (хотя серия содержит регион, это все равно замена)

**ВЫВОД:** Текущая реализация считает KLD для ВСЕХ столбцов, включая замены. Это завышает и искажает результат!

### Проблема №2: Высокий KLD = НЕ баг, а ОСОБЕННОСТЬ агрессивного обобщения

Для обобщения типа "529 значений → 2 значения":
- KLD ~20-30 это НОРМАЛЬНО
- Это отражает РЕАЛЬНУЮ степень изменения распределения

## 💡 ПРАВИЛЬНОЕ РЕШЕНИЕ

### 1. РАЗДЕЛИТЬ атрибуты по типу обезличивания

**Группа A: ОБОБЩЕНИЕ** (считаем KLD):
- Симптомы
- Выбор врача
- Дата посещения
- Анализы
- Дата получения
- Стоимость

**Группа B: ЗАМЕНА** (НЕ считаем KLD):
- ФИО
- Паспорт
- СНИЛС
- Карта (спорно)

### 2. ДОБАВИТЬ метрику Information Loss

Information Loss = 1 - (unique_after / unique_before)

Пример для ваших данных:
```
ФИО:            IL = 99.3% (277 → 2)
Паспорт:        IL = 91.0% (277 → 25)
СНИЛС:          IL = 97.8% (277 → 6)
Симптомы:       IL = 99.6% (553 → 2)
Выбор врача:    IL = 70.4% (54 → 16)
Дата посещения: IL = 99.6% (529 → 2)
Стоимость:      IL = 90.3% (62 → 6)
```

**Интерпретация IL:**
- IL < 50%: Низкая потеря информации
- IL 50-80%: Средняя потеря
- IL 80-95%: Высокая потеря
- IL > 95%: Очень высокая потеря (почти полная замена)

### 3. ПОКАЗЫВАТЬ контекст в GUI

Вместо:
```
❌ KLD = 21.77 (Очень низкая полезность)
```

Показывать:
```
✓ KLD = 21.77
  Интерпретация: Агрессивное обобщение (ожидаемо для высокой анонимности)
  
  Детали по столбцам (только обобщение):
  - Симптомы: KLD=24.9, IL=99.6% (553→2 значения)
  - Врачи: KLD=27.8, IL=70.4% (54→16 значений)
  - Даты: KLD=24.4, IL=99.6% (529→2 значения)
  
  ⚠️ Высокий KLD = сильное обобщение = лучшая K-anonymity
  ⚠️ Компромисс: анонимность ↑ vs полезность ↓
```

## 🔍 ОТВЕТ НА ВОПРОС ПРО ОДИНАКОВЫЕ KLD

**Вопрос:** "Почему KLD одинаковые при USE_SPECIFIC_BANK_NAME=True и False?"

**Ответ:**
1. Изменяется только столбец "Карта оплаты" (1 из 10)
2. Общий KLD = среднее по всем столбцам
3. Изменение одного столбца дает ~10% изменения общего KLD
4. При KLD~21: изменение ~2 единицы может быть незаметно

**ПРОВЕРКА** (если считать KLD только для "Карты оплаты"):
- True: KLD_карты = X
- False: KLD_карты = Y
- Разница (X-Y) должна быть видна

**РЕШЕНИЕ:** Показывать KLD ПО СТОЛБЦАМ, а не только общий!

]

def evaluate_utility_correct(self, original_df, anonymized_df):
    # KLD только для обобщенных
    kld_results = self.calculate_kld(original_df, anonymized_df, GENERALIZATION_COLUMNS)
    
    # Information Loss для всех
    il_results = self.calculate_information_loss(original_df, anonymized_df)
    
    return {
        'kld_by_column': kld_results,
        'information_loss': il_results,
        'overall_kld': np.mean([v for v in kld_results.values() if v]),
        'overall_il': np.mean([v for v in il_results.values() if v])
    }
